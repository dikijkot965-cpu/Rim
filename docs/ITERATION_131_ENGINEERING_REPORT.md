# RIM 4.1.4 — iteration 131

## Исправление push-уведомлений

Предыдущая версия намеренно отправляла только нейтральный текст «Новое сообщение». Это не соответствовало запросу владельца на привычные уведомления уровня Telegram. В iteration 131 поведение изменено:

- Личная переписка: заголовок — отображаемое имя отправителя; текст — превью сообщения.
- Группа: заголовок — отправитель; текст — название группы и превью.
- Канал: заголовок — название канала; текст — превью публикации.
- Иконка уведомления использует аватар отправителя/канала, если доступен HTTPS URL или подписанная ссылка Storage; иначе используется значок РИМ.
- Push-подписка фильтруется по `messages_enabled` или `channel_posts_enabled` и `push_enabled`.
- `show_message_preview` позволяет скрыть имена и текст на уровне настроек пользователя. По умолчанию включено.
- Новая публикация канала вызывает `rim-push` после успешной записи. Ошибка push не откатывает публикацию.
- Push-полезная нагрузка содержит только необходимый контекст уведомления; вложения и полные объекты сообщений не передаются.
- Service Worker кликабельного уведомления открывает/фокусирует РИМ.
- Все части приложения используют единый `/service-worker.js`; устранено расхождение между `/sw.js` и `/service-worker.js`.

Supabase Edge Function `rim-push` развёрнута как version 4 с `verify_jwt=true`. Миграция добавила `notification_preferences.show_message_preview` и расширила allow-list rate limiter для `push_channel_post`.

## Каналы

- Добавлены точные счётчики подписчиков и администраторов в read model профиля канала.
- Для администратора отображаются быстрые действия: приглашение, новая публикация, настройки; ссылка на обсуждение показывается только если оно реально привязано к каналу.
- Для подписчика остаются публичная информация и действие подписки/отписки; административные данные не показываются.
- Счётчики запрашиваются агрегатными HEAD/count запросами, а не загружают весь список участников.
- Рендер реакций и голосов оптимизирован: группировка в Map выполняется один раз, вместо повторной фильтрации полных массивов для каждой публикации/опроса.

## Seed-only: фактический статус

Auth Hook подключён, Edge Function `rim-account-security` v12 развёрнута, но полный E2E на отдельном тестовом аккаунте не выполнялся. Поэтому readiness-флаг временно возвращён в `false`. Ни один аккаунт не переведён в seed-only. Это сделано намеренно: не давать пользователю включить строгий режим, пока не проверены seed-вход, refresh, отказ OAuth/OTP/magic link, отзыв старых сессий и безопасное отключение режима.

Форматы фраз остаются собственными форматами РИМ: 24 слова (184 бита энтропии + 8-битная контрольная сумма) и 12 слов (128 бит + 4-битная контрольная сумма). 12 слов — более удобный, но математически менее стойкий вариант. Оба не совместимы с BIP-39.

## Уведомления: подключение

В `tools/vapid-keygen.html` добавлен автономный браузерный генератор VAPID-ключей на Web Crypto. Node.js и онлайн-генератор не требуются. Полная инструкция — `docs/PUSH_NOTIFICATIONS_SETUP.md`.

Для включения доставки владельцу нужно сгенерировать пару и добавить `RIM_VAPID_PUBLIC_KEY`, `RIM_VAPID_PRIVATE_KEY`, `RIM_VAPID_SUBJECT` в Supabase Edge Function Secrets, затем опубликовать обновлённый frontend и разрешить уведомления в Android/браузере.
