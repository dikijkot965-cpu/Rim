# Ручная загрузка RIM в GitHub с Android

Этот пакет предназначен для ручной загрузки владельцем репозитория. Никакой workflow для распаковки ZIP и автоматической замены репозитория не требуется.

## Перед загрузкой

1. Открой `dikijkot965-cpu/Rim` на GitHub.
2. Убедись, что выбрана ветка `main`.
3. Скачай ZIP и распакуй его на телефоне.
4. Открой папку `RIM_4.1.8_ITERATION_172`.
5. Выдели **содержимое этой папки**, а не саму папку верхнего уровня, и загрузи файлы в корень репозитория.
6. Если GitHub предлагает заменить существующий файл — замени его новой версией. Не создавай второй вложенный каталог `RIM_4.1.8_ITERATION_172` внутри репозитория.
7. Сделай commit в `main`. GitHub Pages соберёт сайт обычным способом, настроенным в репозитории.

GitHub через мобильный браузер может ограничивать количество файлов за одну загрузку. Если так происходит, загружай содержимое отдельными папками, сохраняя структуру путей из ZIP. Не меняй имена и регистр каталогов.

## Что обязательно сохранить в репозитории

Не удаляй эти пути при ручной очистке:

- `index.html` — входная страница GitHub Pages.
- `assets/` — CSS, JS bundle, SQLite worker/WASM, изображения и иконки.
- `src/` — исходные модули, из которых собирается приложение.
- `supabase/` — миграции и исходники Edge Functions.
- `package.json`, `package-lock.json` — закреплённые зависимости и команды сборки.
- `scripts/` — проверки и сборка.
- `vendor/` — закреплённый архив Signal SDK, используемый offline/bootstrap-сценариями.
- `manifest.json`, `service-worker.js`, `icons/` — PWA.
- `wrangler.jsonc`, `cloudflare-pages/`, `dist/` — существующие Cloudflare deployment outputs/config; не удалять, если Cloudflare Pages/Worker остаётся подключён.
- `bot-runtime/` — отдельный runtime пользовательских ботов.
- `tests/`, `docs/`, `sql/` — проверки, документация и дополнительные SQL-материалы.
- `.github/workflows/` — существующие CI workflows; не удаляй их без отдельной проверки назначения.

## Что можно удалить

В этом пакете удалён только `deploy-rim-project-zip.yml`, потому что ручная загрузка ZIP не должна запускать автоматическую замену репозитория.

Можно удалять только локальные временные артефакты, которые не являются частью репозитория: распакованные дубликаты ZIP на телефоне, скачанные отчёты и старые копии архива. В самом репозитории безопасный список удаления пока не установлен. Не удаляй `legacy/` только по названию: эти файлы могут оставаться входными зависимостями или частью обратной совместимости.

## Supabase — отдельно от GitHub

Загрузка файлов в GitHub не применяет SQL к Supabase и не развёртывает Edge Functions. В активном проекте RIM (`xxvcsaomkyknudoaixbs`) уже существуют миграции E2E 164/165/165a/167/168, функции `rim-e2e-relay`, `rim-e2e-device-link`, `rim-zladen`, а также секретные direct chats и E2E scope RPC. Миграция Zladen group-arrival (139), отсутствовавшая в migration history, была применена отдельно в этой рабочей сессии.

Не запускай миграции повторно вручную только потому, что они отсутствуют в ZIP. Перед любым SQL применением сверяй `supabase migration list`/Supabase migration history. История живой базы и SQL-файлы в ZIP пока не полностью синхронизированы: миграции 164/165/165a/167/168 были созданы и применены после Iteration 163, а их исходные SQL-файлы не входят в этот архив. В Iteration 172 восстановлен исходник уже существующих production RPC/trigger E2E; файл Iteration 172 не применялся повторно. Миграции Zladen 170/171 есть в исходниках, но отсутствуют в production migration history и не должны считаться активными до отдельного применения. Этот релиз не выдаёт их за применённые.
