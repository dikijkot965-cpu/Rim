# Настройка push-уведомлений РИМ (Android / браузер)

## Как будут выглядеть уведомления

- Личная переписка: имя отправителя в заголовке, текст сообщения в описании, аватар отправителя при наличии.
- Группа: имя отправителя в заголовке, название группы и фрагмент сообщения в описании.
- Канал: название канала в заголовке, фрагмент публикации и аватар канала при наличии.
- В настройках РИМ можно отключить показ имени/чата/текста через `show_message_preview`.
- Android может скрывать содержимое на заблокированном экране согласно системным настройкам приватности.

## Шаг 1. Сгенерировать ключи без Node.js

1. Распакуйте архив RIM на телефоне или компьютере.
2. Откройте файл `tools/vapid-keygen.html` в современном браузере. Генератор работает локально через Web Crypto и не отправляет ключи в интернет.
3. Нажмите «Сгенерировать новую пару».
4. Скопируйте публичный и приватный ключи. Не обновляйте страницу, пока не внесли их в Supabase.
5. Для `RIM_VAPID_SUBJECT` укажите `mailto:ВАШ_РЕАЛЬНЫЙ_EMAIL` или HTTPS URL сайта.

Если браузер сообщает, что Web Crypto недоступен, откройте этот файл через HTTPS либо используйте актуальный Chrome/Firefox. Не вставляйте приватный ключ в онлайн-генераторы.

## Шаг 2. Сохранить секреты в Supabase

1. Откройте Supabase Dashboard и выберите проект РИМ.
2. Перейдите в **Edge Functions → Secrets** (в некоторых вариантах панели — **Project Settings → Edge Functions → Secrets**).
3. Добавьте три секрета с точными именами:
   - `RIM_VAPID_PUBLIC_KEY` — публичный ключ.
   - `RIM_VAPID_PRIVATE_KEY` — приватный ключ.
   - `RIM_VAPID_SUBJECT` — `mailto:...` или HTTPS адрес.
4. Сохраните изменения. Не добавляйте эти значения в `index.html`, JavaScript, GitHub или ZIP.

## Шаг 3. Опубликовать frontend

1. Загрузите содержимое папки `cloudflare-pages` в текущий Cloudflare Pages deployment (либо используйте ваш существующий pipeline).
2. Убедитесь, что сайт открывается по HTTPS.
3. В браузере откройте РИМ, войдите в аккаунт → Настройки → Уведомления.
4. Включите «Push-уведомления» и нажмите «Подключить push на этом устройстве».
5. Разрешите уведомления в запросе браузера и в системных настройках Android.
6. Проверьте тестом: отправьте личное сообщение со второго аккаунта; отдельно опубликуйте пост в канале, на который подписан тестовый аккаунт.

## Если уведомления не приходят

- Проверьте, что VAPID public/private keys — одна пара, а subject начинается с `mailto:` или `https://`.
- Проверьте, что браузер разрешил уведомления и у устройства есть интернет.
- Убедитесь, что `push_enabled=true`, а для личных сообщений `messages_enabled=true`; для канала `channel_posts_enabled=true`.
- Если Android ограничивает фоновую работу браузера, разрешите ему фоновую активность/автозапуск в настройках системы.
- При повторной привязке другого аккаунта на том же браузерном профиле сначала отключите push у прежнего аккаунта.

## Ограничения

Push доставляется браузерным Push API. На Android это зависит от браузера/установленного PWA и системных ограничений энергосбережения. Это не гарантирует доставку при принудительной остановке приложения/браузера или отключённой сети. Содержимое push шифруется Web Push между отправителем и push service/browser endpoint, но push provider и ОС остаются частью инфраструктуры доставки.
